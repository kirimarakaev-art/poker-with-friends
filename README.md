# Покер с друзьями

[![CI](https://github.com/kirimarakaev-art/poker-with-friends/actions/workflows/ci.yml/badge.svg)](https://github.com/kirimarakaev-art/poker-with-friends/actions/workflows/ci.yml)

Сайт, где можно сыграть в покер с друзьями прямо в браузере. Играть: **https://78-17-98-149.sslip.io** Можно создать закрытый стол и отправить друзьям код или сесть за открытый стол из списка.

- **Texas Hold'em No-Limit**, от 2 до 9 игроков.
- **Только фишки**, никаких реальных денег.
- **Честная игра:** карты тасует сервер, а чужие карты не уходят клиенту до вскрытия.

Бэкенд написан на Go, фронтенд — на React + TypeScript.

## Что уже умеет сервер

- Создать комнату с блайндами и стартовым стеком и получить 6-символьный код-приглашение.
- Сесть за стол по коду или из списка открытых столов, взяв фишки с баланса.
- Полная раздача: блайнды → префлоп → флоп → тёрн → ривер → вскрытие. Следующая раздача начинается сама, баттон сдвигается.
- Все действия: fold, check, call, bet, raise, all-in, со всеми правилами No-Limit. Учтены хедз-ап, право хода большого блайнда, минимальный рейз и то, что короткий олл-ин не открывает торговлю заново.
- Банки и **сайд-поты**, возврат неуравненных ставок, делёж банка при ничьей.
- Таймер хода 30 секунд: кто не успел, за того автоматически чек или фолд.
- Переподключение: игрок возвращается на своё место с теми же картами, его узнают по сессии.
- Чат за столом.
- Выход из-за стола: кто в раздаче, выходит после неё. Игрок без фишек остаётся наблюдать, а кто не в сети больше 5 минут, теряет место.
- Аккаунты: регистрация и вход, баланс фишек (10 000 при регистрации, ежедневный бонус), бай-ин при посадке за стол и возврат стека при уходе, статистика раздач.
- Главное меню: открытые столы, свои столы, создание открытого или закрытого стола, вход по коду.
- Админ-панель на `/admin` для аккаунта с ролью админа: столы, выкинуть игрока, закрыть комнату, пользователи и их баланс.
- PostgreSQL: комнаты, игроки и история раздач сохраняются, после перезапуска сервера игроки возвращаются за свои столы.

## Быстрый старт

Через Docker — соберёт фронтенд и сервер, поднимет PostgreSQL, игра откроется на http://localhost:8080:

```bash
docker compose up --build
```

Или напрямую (нужен Go 1.27.2+):

```bash
go run ./cmd/server            # http://localhost:8080, комнаты только в памяти
```

С базой данных сервер получает адрес из `DATABASE_URL`, сам применяет миграции и восстанавливает комнаты:

```bash
DATABASE_URL='postgres://poker:poker@localhost:5432/poker?sslmode=disable' go run ./cmd/server
```

Сервер может сам отдавать собранный фронтенд — тогда сайт, API и WebSocket живут на одном адресе, без прокси:

```bash
(cd frontend && npm ci && npm run build)
go run ./cmd/server -static frontend/dist
```

Порт можно сменить через `PORT`, если 8080 занят: `PORT=8081 docker compose up --build`.

Попробовать без фронтенда можно прямо из консоли браузера на `http://localhost:8080`:

```js
const post = (u, b) => fetch(u, {method: "POST", body: JSON.stringify(b)}).then(r => r.json());
const {code} = await post("/api/rooms", {smallBlind: 5, bigBlind: 10, stack: 1000});
const {token} = await post(`/api/rooms/${code}/join`, {name: "Ann"});
const ws = new WebSocket(`ws://${location.host}/ws?room=${code}&token=${token}`);
ws.onmessage = e => console.log(JSON.parse(e.data));
```

Полное описание HTTP API и WebSocket-протокола: [docs/API.md](docs/API.md). Требования к фронтенду: [docs/FRONTEND.md](docs/FRONTEND.md) и [этап 2: отображение и анимации](docs/FRONTEND-STAGE2.md).

## Деплой на VPS

Нужен сервер с Ubuntu и Docker, порты 80 и 443 открыты. Игру отдаёт Caddy: он сам получает HTTPS-сертификат Let's Encrypt и продлевает его. Наружу смотрит только Caddy, сервер игры и база доступны лишь внутри Docker.

Свежий сервер настраивается одним скриптом с вашего компьютера: он создаёт пользователя `deploy` с вашими SSH-ключами, запрещает вход по паролю и под root, открывает только SSH, HTTP и HTTPS, ставит Docker и добавляет swap.

```bash
ssh root@<IP сервера> 'bash -s' < scripts/setup-server.sh
```

Первый запуск (дальше всё под пользователем `deploy`):

```bash
git clone https://github.com/kirimarakaev-art/poker-with-friends.git /opt/poker
cd /opt/poker
cp .env.example .env
openssl rand -hex 24      # вставьте результат в POSTGRES_PASSWORD в .env
nano .env                 # SITE_ADDRESS — адрес сайта, ADMIN_USERNAME — логин админа
scripts/deploy.sh
```

Админ-панель — на `/admin`. Админом становится аккаунт с логином из `ADMIN_USERNAME`: в панели список столов и игроков, «выкинуть», закрыть комнату, список пользователей и их баланс.

Обновить до свежей версии из git — снова `scripts/deploy.sh`. Логи:

```bash
docker compose -f compose.yaml -f compose.prod.yaml logs -f
```

На этом же сервере можно держать и другие сайты: Caddy подключает файлы `/opt/caddy-sites/*.caddy` (один файл на сайт, например `go.78-17-98-149.sslip.io { reverse_proxy golang-site:3000 }`). Контейнер сайта должен быть в общей сети Docker `web`. После добавления файла: `docker compose -f compose.yaml -f compose.prod.yaml exec caddy caddy reload --config /etc/caddy/Caddyfile`.

Для быстрой проверки без сервера можно открыть локальную игру в интернет командой `ssh -R 80:localhost:8080 nokey@localhost.run`, но ссылка меняется при каждом подключении и часто обрывается.

## Архитектура

```
Браузер ──HTTP──────► lobby       создать комнату, сесть за стол
        ──WebSocket─► client      одно соединение = один игрок
                          │
                          ▼
                       table       одна горутина на стол
                          │
                          ▼
                       engine      чистая логика покера, без сети
```

Главный принцип: **сервер — единственный источник правды.** Клиент присылает только намерение («рейз до 200»). Сервер проверяет правила, меняет состояние и рассылает каждому игроку *его* версию стола.

Решения, которые стоит посмотреть в коде:

- **Стол как актор** ([internal/server/table.go](internal/server/table.go)). Всё состояние стола принадлежит одной горутине, а остальные передают ей изменения функциями через канал. Поэтому внутри стола нет мьютексов и гонок данных, а таймеры и ходы игроков обрабатываются строго по очереди.
- **Свой вид стола для каждого игрока** ([internal/server/view.go](internal/server/view.go)). Чужие карты не скрываются в интерфейсе, а просто не отправляются, пока не наступило вскрытие.
- **Тасовка** ([engine/shuffle.go](engine/shuffle.go)): Фишер–Йетс на генераторе ChaCha8 с сидом из `crypto/rand`. У каждого стола свой генератор.
- **Оценка руки без перебора 21 пятёрки** ([engine/hand.go](engine/hand.go)): счётчики рангов и битовые маски, где стрит — это 5 единиц подряд.
- **Сайд-поты** ([engine/pots.go](engine/pots.go)): банк режется на уровнях олл-инов, а фишки сбросивших остаются в игре.
- **База не тормозит стол** ([internal/server/persist.go](internal/server/persist.go)): стол не ждёт PostgreSQL, а кладёт записи в очередь, которую по порядку разбирает отдельная горутина. Раздача и новые стеки пишутся одной транзакцией ([internal/store/postgres.go](internal/store/postgres.go)), миграции на goose встроены в бинарник. Токены игроков хранятся только в виде SHA-256.
- **Медленный клиент не тормозит стол** ([internal/server/client.go](internal/server/client.go)): у каждого соединения своя очередь отправки. Кто не успевает читать, того отключают, а он может переподключиться.

## Структура

```
cmd/server/        точка входа
engine/            движок: карты, колода, оценка рук, торговля, банки
internal/server/   HTTP API, WebSocket, столы, протокол
internal/store/    PostgreSQL: схема, миграции, запросы

```

## Тесты

```bash
go test ./...              # всё, включая полный перебор рук из 5 карт
go test -short ./...       # без медленного перебора
go test -race -cover ./... # как в CI
```

Тесты базы данных запускаются, только если задан `TEST_DATABASE_URL`. Каждый тест работает в своей временной схеме:

```bash
docker run -d --name poker-pg-test -e POSTGRES_PASSWORD=test -e POSTGRES_DB=poker_test -p 55432:5432 postgres:18.6-alpine
TEST_DATABASE_URL='postgres://postgres:test@localhost:55432/poker_test?sslmode=disable' go test ./internal/store/
```

- **Движок:** покрытие около 98%. Частоты всех категорий проверены на всех 2 598 960 руках из 5 карт. Оценка 7 карт сверена с перебором всех пятёрок на 20 000 случайных рук. Тысячи случайных раздач проверяют, что фишки не теряются и выплаты равны вложенному.
- **Сервер:** покрытие около 91%. Интеграционные тесты поднимают настоящий HTTP-сервер и подключаются настоящими WebSocket-клиентами: скрытые карты, вскрытие, таймер, переподключение, выход из-за стола, админка, ошибки.
- **База данных:** тесты хранилища идут на настоящем PostgreSQL, а сервер проверяется с хранилищем в памяти: что сохраняется после раздачи и что комнаты переживают перезапуск.
- **CI** (GitHub Actions) на каждый push в `main` и на каждый pull request: `gofmt`, `go vet`, `staticcheck`, тесты с `-race` вместе с PostgreSQL.
