# ТЗ: фронтенд «Покер с друзьями» (MVP)

## Цель

Браузерный клиент, в котором компания друзей может создать закрытый стол, позвать друг друга по ссылке и сыграть в Texas Hold'em No-Limit на фишки. Бэкенд готов, фронтенд работает только через его API.

## Что уже есть

- **Бэкенд на Go** в `main`: комнаты, игра по WebSocket, таймер хода, переподключение, чат.
- **Описание API и протокола:** [docs/API.md](API.md). Это главный документ: все поля, ошибки, коды закрытия соединения и TypeScript-типы.
- **Запуск бэкенда без Go:** `docker compose up --build` (порт 8080).
- **CI** на GitHub Actions проверяет каждый pull request.
- **Ветка `feature/frontend-v2`** — хорошая основа, работа продолжается в ней. Что в ней уже сделано, а что нет, см. в разделе «[Состояние ветки](#состояние-ветки-featurefrontend-v2)» в конце.

## Стек и ограничения

- React 18 + TypeScript (strict) + Vite. Новые зависимости — только если без них никак.
- Все запросы идут по относительным путям (`/api/...`, `/ws`), без захардкоженных адресов. В продакшене Go-сервер будет сам отдавать собранный фронтенд с того же адреса.
- В разработке используется прокси Vite из [docs/API.md](API.md#разработка-с-vite-обязательно-через-прокси).

## Экраны и сценарии

### 1. Главная (`/`)

- Две кнопки: «Создать комнату» и «Войти по коду».
- **Создание:** ник (1–20 символов), малый и большой блайнд, стартовый стек. Перед отправкой проверить: `0 < малый ≤ большой ≤ стек ≤ 1 000 000`. Затем `POST /api/rooms` → `POST /api/rooms/{code}/join` → сохранить токен → перейти на `/?room=CODE`.
- **Вход:** ник и код комнаты (регистр не важен) → `join` → сохранить токен → `/?room=CODE`.
- Ошибки сервера показываются понятным текстом: «Комната не найдена», «За столом нет мест», «Неверные параметры комнаты».

### 2. Ссылка-приглашение (`/?room=CODE`)

- Если для этой комнаты в `localStorage` есть токен, сразу подключаться к столу без ввода ника.
- Если токена нет, показать форму ника с уже подставленным кодом.
- Если в ответ пришёл код закрытия 1008 (токен не действует), удалить токен и показать форму ника.
- Если комнаты нет (404), показать «Комната не найдена» и кнопку «На главную».

### 3. Стол

**Шапка:**
- **код комнаты и кнопка «Скопировать приглашение»**, которая копирует ссылку `https://<адрес>/?room=CODE`. В ссылке **никогда нет токена**;
- номер раздачи, улица, таймер хода.

**Места игроков** (из `players`, по `seat`):
- ник, стек, ставка на улице;
- метки: «Вы» (по `you`, а не по нику), баттон «D», чей ход (`toAct`), сбросил, олл-ин, не в сети (`connected: false`), ждёт следующей раздачи (`inHand: false`);
- **карты:** свои всегда, чужие лицом — только когда пришло поле `cards`. Рубашки рисуются, если игрок `inHand`, не `folded` и поля `cards` нет;
- после раздачи — выигрыш из `won`.

**Центр стола:**
- банк (`pot`);
- 5 мест под общие карты: пришедшие карты лицом, на остальных местах **пустые рамки, а не рубашки**.

**Отображение карт:** ранг `T` показывать как «10», масти ♥ и ♦ красным.

**Панель действий** (активна только в свой ход, все условия берутся из `options`):
- «Фолд» доступен всегда в свой ход.
- «Чек» — если `canCheck`.
- «Колл N» — если `callAmount > 0`.
- «Бет до» или «Рейз до» — если `canRaise`. Какую подпись показать, решает `currentBet === 0`. **`amount` — это итоговая ставка на улице**, а не прибавка. Поле суммы ограничено `minRaiseTo`…`maxRaiseTo`. Удобно добавить кнопки-подсказки: «мин», «½ банка», «банк», «макс».
- «Олл-ин» — если `canRaise` или если `callAmount` равен стеку игрока. На кнопке показывается стек игрока.
- **Введённая сумма не сбрасывается** от любого входящего `state`, только при смене раздачи или улицы и при выходе за границы.

**Чат:** список сообщений и поле ввода (1–200 символов). Сообщения приходят всем, включая отправителя, поэтому своё сообщение не нужно дорисовывать локально.

**Ошибки хода:** показывать «Ход не принят» на 3–4 секунды. Текст сервера выводить в `console.warn`, игроку его не показывать.

### 4. Соединение

- **Обрыв связи** (любой код, кроме 4001 и 1008): плашка «Переподключение…» и повторные попытки с паузами 1 → 2 → 5 → 10 → 10… секунд. Пришёл `state` — плашку убрать, счётчик сбросить.
- **4001:** экран «Вы открыли игру в другом окне» с кнопкой «Играть здесь». Автоматически не переподключаться.
- **1008:** см. пункт 2.
- Обновление страницы на `/?room=CODE` возвращает игрока за стол с теми же картами.

## Не входит в MVP

- Аккаунты, история раздач, статистика.
- Выход из-за стола, докупка фишек, кик игрока: сервер этого пока не умеет.
- Звуки и анимации.
- Полноценная мобильная вёрстка. Желательно только, чтобы на телефоне шириной 375 px стол читался, а кнопки нажимались.

## Как сдавать

- Работать в `feature/frontend-v2`. Перед PR подтянуть свежий `main`.
- Открыть **pull request в `main`**. CI должен быть зелёным, `npm run build` (то есть `tsc` + сборка) — без ошибок.
- В репозитории не должно быть `node_modules`, `dist`, CRLF (это уже настроено через `.gitignore` и `.gitattributes`).
- В описании PR указать, что сделано и как проверить.

## Приёмка

Сценарий прогоняется в трёх разных браузерах или окнах (обычное, приватное, другой браузер):

1. A создаёт комнату и копирует приглашение. B и C открывают ссылку, вводят ники и садятся.
2. Раздача начинается сама. Каждый видит только свои карты, у соперников рубашки, баттон и чей ход видны, таймер идёт.
3. A делает рейз через поле суммы с кнопкой «½ банка». Во время ввода C отключается и подключается снова, а введённая сумма **не сбрасывается**. B уравнивает. C не ходит, и через 30 секунд за него срабатывает автоматический фолд.
4. Игра до вскрытия: карты дошедших до вскрытия открываются, видно, кто сколько выиграл, через 3 секунды начинается новая раздача.
5. Короткий стек идёт в олл-ин, и на вскрытии правильно показан выигрыш с сайд-потом.
6. B обновляет страницу и сразу возвращается за стол с теми же картами.
7. B открывает ту же ссылку в другой вкладке: первая показывает «Вы открыли игру в другом окне», «Играть здесь» возвращает игру в неё.
8. Остановить и снова запустить бэкенд: появляется «Переподключение…». После перезапуска комната пропадает (это нормально), клиент показывает «Комната не найдена» и не зацикливается.
9. Неверная сумма рейза (меньше минимума, введённая вручную) даёт «Ход не принят», игра не ломается.
10. Чат работает у всех троих.

## Приоритеты

1. Код комнаты, приглашение и вход по ссылке (без этого нельзя позвать друзей).
2. Возврат после обновления страницы и переподключение при обрыве.
3. Поле суммы, которое не сбрасывается, и правило для «Олл-ин».
4. Остальное: «10» вместо «T», пустые места на столе, понятные ошибки, кнопки-подсказки суммы.
